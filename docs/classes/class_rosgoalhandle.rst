RosGoalHandle
=============

**Inherits:** `RefCounted <https://docs.godotengine.org/en/stable/classes/class_refcounted.html>`__

A handle that tracks the lifecycle of a goal sent through a :ref:`RosActionClient<class_RosActionClient>`.

.. rst-class:: classref-introduction-group

Description
-----------

**RosGoalHandle** is returned by :ref:`RosActionClient.send_goal()<class_RosActionClient_method_send_goal>` and behaves like a promise: you can poll it with :ref:`is_completed()<class_RosGoalHandle_method_is_completed>` and :ref:`get_result()<class_RosGoalHandle_method_get_result>`, or connect to (and ``await``) its signals.

All signals are emitted on the Godot main thread, so it is always safe to touch the scene tree from their handlers.

The typical lifecycle is: :ref:`accepted<class_RosGoalHandle_signal_accepted>` (or :ref:`rejected<class_RosGoalHandle_signal_rejected>`) → zero or more :ref:`feedback<class_RosGoalHandle_signal_feedback>` emissions → :ref:`completed<class_RosGoalHandle_signal_completed>` with the final result and status.

\ **Note:** If the goal is rejected by the server, :ref:`completed<class_RosGoalHandle_signal_completed>` is still emitted (with a ``null`` result and :ref:`STATUS_UNKNOWN<class_RosGoalHandle_constant_STATUS_UNKNOWN>`) so that ``await handle.completed`` never hangs.

|void| **cancel**\ (\ ) :ref:`🔗<class_RosGoalHandle_method_cancel>`

Asks the server to cancel this goal. Cancellation is cooperative: the server decides when (and whether) to stop. The outcome still arrives through :ref:`completed<class_RosGoalHandle_signal_completed>`, with :ref:`STATUS_CANCELED<class_RosGoalHandle_constant_STATUS_CANCELED>` if the cancellation was honored.
