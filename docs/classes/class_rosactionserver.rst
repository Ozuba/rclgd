RosActionServer
===============

**Inherits:** `RefCounted <https://docs.godotengine.org/en/stable/classes/class_refcounted.html>`__

A ROS 2 Action Server that executes long-running goals from clients.

.. rst-class:: classref-introduction-group

Description
-----------

**RosActionServer** lets Godot act as a server for ROS 2 actions. It is created through :ref:`RosNode.create_action_server()<class_RosNode_method_create_action_server>`, passing an execute callback.

Incoming goals are accepted automatically and handed to the execute callback on the Godot main thread as a :ref:`RosServerGoalHandle<class_RosServerGoalHandle>`. Cancel requests are accepted automatically too; the execute callback observes them by polling :ref:`RosServerGoalHandle.is_cancel_requested()<class_RosServerGoalHandle_method_is_cancel_requested>`.

The execute callback must drive every goal to exactly one terminal state: :ref:`RosServerGoalHandle.succeed()<class_RosServerGoalHandle_method_succeed>`, :ref:`RosServerGoalHandle.abort()<class_RosServerGoalHandle_method_abort>` or :ref:`RosServerGoalHandle.canceled()<class_RosServerGoalHandle_method_canceled>`. Because the callback runs on the main thread, long-running goals should spread their work over frames with ``await`` rather than blocking.

::

    var server = ros_node.create_action_server("fibonacci", "example_interfaces/action/Fibonacci",
        func(goal_handle):
            var sequence = [0, 1]
            for i in range(2, goal_handle.get_goal().order):
                sequence.append(sequence[i - 1] + sequence[i - 2])
                var fb = goal_handle.create_feedback()
                fb.sequence = sequence
                goal_handle.publish_feedback(fb)
                await get_tree().process_frame
            var result = goal_handle.create_result()
            result.sequence = sequence
            goal_handle.succeed(result)
    )

Keep a reference to the returned server object: like every rclgd interface it unregisters from the ROS graph when it is freed.
